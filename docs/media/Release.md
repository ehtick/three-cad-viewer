# Releasing a new version

The order matters: `yarn build` regenerates the tracked file `src/_version.ts` from `package.json`, so the build has to run **before** the first commit — otherwise that commit carries the new version in `package.json` and the old one in `src/_version.ts`.

1. Bump the version

   Edit `version` in `package.json`. Nothing else needs editing; `src/_version.ts` is generated by the build.

2. Write the changelog entry

   Add a `## v<version>` section at the top of `Changes.md`. It is written by hand, nothing generates it. Note that `Changes.md` is not part of the npm tarball (it is not listed in `files`, and npm — unlike `yarn pack` — does not ship it implicitly).

3. Clean and build

   ```shell
   yarn run clean
   yarn run build
   ```

   This rewrites `src/_version.ts` with the new version and produces the four bundles plus the CSS in `dist/`.

4. Run the checks

   ```shell
   yarn test:run
   yarn lint
   ```

5. Commit the version

   Stage `package.json`, `src/_version.ts` and `Changes.md` together.

   ```shell
   git commit
   ```

6. Create the docs

   ```shell
   yarn run docs
   ```

   `scripts/build_docs.sh` deletes and regenerates the whole `docs/` tree (including the committed `docs/dist/` copy that GitHub Pages serves), so stage the deletions as well.

   ```shell
   git add -A docs
   git commit
   ```

7. Publish the package

   ```shell
   npm login
   npm publish        # npm publish --dry-run first to inspect the tarball
   npm logout
   ```

   `npm publish` triggers the `prepare` hook, which runs `yarn run build` again before packing.

8. Push the release, e.g. 5.0.6

   Ensure `gh` is authenticated (or `GITHUB_TOKEN` is set)!

   ```shell
   yarn run release
   ```

   `scripts/release.sh` tags `v<version>`, pushes the branch and the tags, and creates the GitHub release with the `dist/` assets. This is the only step that pushes anything to GitHub, and it does not build — `dist/` has to be the one from step 3. The script does not check whether the tag already exists, so delete a leftover tag before re-running it.
